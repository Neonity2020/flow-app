# AI 工作流

## 对话策略

AI 围绕目标、具体场景、输入输出、范围、交互、数据和验收逐步 grill。优先处理会改变方案的关键问题，每轮聚焦少量问题，并给出推荐方案和取舍理由。

明确区分用户确认、AI 建议和未决假设。遇到矛盾创建问题并要求选择；用户明确回答后更新决策和关联内容。画布是结构化思考结果，对话是过程记录。

## 一轮运行

1. 校验项目存在且没有活跃任务，保存用户消息并创建 run。
2. 冻结选择范围、画布修订、相关历史和当前 spec；图片只提供附件存在信息，不提供路径或二进制。
3. 启动 Codex bridge 并提交上下文、角色约束和可用操作 schema。
4. 流式展示回复；结构化操作经服务校验并以批次事务执行。
5. 将操作结果或冲突返回模型，允许其在限制内修正；结束时持久化最终消息和运行终态。

工具循环需要设置轮数和时间上限，防止无限修正；具体阈值在集成验证时配置。达到限制保留已提交结果，返回可理解的错误。

选中模式中的可操作对象由服务端冻结并校验；新建对象可加入本轮范围。越界操作被拒绝，AI 提示用户扩大范围。全项目背景不等于全项目写权限。

## Codex Bridge

Node-only 模块通过不经过 shell 的子进程启动本机 `codex app-server`。协议细节以安装版本生成的 schema 为准，不靠猜测硬编码。

握手顺序：initialize 响应 → initialized 通知 → thread/start → turn/start。使用空临时 cwd、ephemeral 会话、read-only 沙箱、never approval policy。消费消息 delta 与完成事件，区分模型回复完成和应用操作成功。

AI 普通对话禁止任意文件、shell、浏览器和外部工具。应用工具执行只通过白名单领域服务。本机登录由 `codex login` 完成，应用不保存登录凭据。

动态工具能力优先按实际协议验证。若不适配，采用结构化结果中的 content 与 toolCalls，并将工具 input 表示为 JSON 字符串，经解析、schema 校验后执行；结构化输出对象需关闭未知属性。工具执行结果回传继续推理。

## 生成 Spec

生成任务共享同项目单运行锁。先判断基础信息是否缺失；缺失则返回追问和阻塞问题，不写 spec。其他未决项进入草稿的未决问题列表。

输出内容覆盖目标、场景、范围、流程、功能、数据、AI 行为、异常、验收和未决问题。已有文档和手工编辑作为上下文。模型只返回候选正文，应用在完成时再次校验 specRevision，保存快照并原子替换。

画布运行中发生变化时，新 spec 的来源仍标记为输入快照版本，并显示需要更新；不能声称覆盖了未读取的新内容。spec 本身被编辑则拒绝覆盖。

## 取消与故障

取消先设置取消标记并阻止新批次提交，再终止关联子进程，最终标记 cancelled。取消和提交在事务边界串行协调：提交已完成则保留，未提交则拒绝。清理仅删除本轮生成的临时目录。

服务重启把未终结 run 标记 interrupted。断线后读取状态并重放事件，不重新提交原请求。未安装、未登录、网络和协议故障分别提示解决方式，保持本地编辑可用。

## 集成验证证据

实现时记录本机 Codex 版本与协议生成方式；完成一轮握手和真实推理 smoke test；确认取消无孤儿进程、无凭据进入上下文、浏览器 bundle 不导入 Node bridge。本文描述目标设计，不表示这些验证已经完成。
