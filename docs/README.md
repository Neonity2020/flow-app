# 文档入口

本项目是本地优先、单人使用的 AI 白板笔记工具，以 React Flow 为画布，通过本机 Codex 追问需求并生成项目 spec。

## 阅读顺序

| 文档 | 用途 |
| --- | --- |
| [构建与验证记录](build-status.md) | 当前实现、验证证据与限制 |
| [产品 Spec](spec.md) | 已对齐的产品范围与验收基线 |
| [产品与交互](product.md) | 页面、用户流程和交互状态 |
| [系统架构](architecture.md) | 技术边界、模块职责与 React Flow 集成 |
| [数据与存储](data-model.md) | 数据模型、一致性、附件与迁移 |
| [接口与操作协议](contracts.md) | 服务接口、AI 操作与事件契约 |
| [AI 工作流](ai-workflow.md) | Grill、Codex bridge、生成 spec 与取消 |
| [实施与验收](implementation.md) | 里程碑、测试与交付条件 |
| [技术决策](decisions.md) | 已确认决策及待验证项 |

## 文档维护规则

- `spec.md` 是产品范围与行为的基线，其余文档负责展开设计。发生冲突时先修正文档，不以实现结果倒推需求。
- 已确认需求变更须同步相关文档及验收项，并在技术决策中说明原因。
- “拟定”表示可在不改变产品行为的前提下调整的工程方案；“待验证”不能当作已经实现或验证。
- 实现任务引用对应验收编号；完成状态以代码和验证证据为准，本文档不代表实现已完成。
- 仓库 `docs/spec.md` 描述本工具；应用中每个项目生成的 spec 存储在数据库，二者不是同一份文档。
