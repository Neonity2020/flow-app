# AI Native 白板笔记工具 — MVP Spec

状态：需求已对齐，可进入实现。日期：2026-10-16。

## 1. 产品目标

面向我们自己使用的、本地优先的单人项目思考工具。用户在无限画布上记录开发思路，通过 AI 持续追问、挑战假设和要求取舍，将零散想法收敛为一份可执行的项目 spec。

核心闭环：项目想法 → AI grill → 画布整理与决策 → 点击按钮生成 spec → 继续讨论并更新同一份 spec。

成功标准：用户能从一句模糊的项目想法出发，在同一项目内完成问题澄清、查看决策及理由、生成和导出包含验收标准的 spec；刷新或重启后内容仍然存在。

## 2. 范围与边界

MVP 包含：多个项目、每项目一张无限画布、一份对话记录、一份当前 spec；四类卡片；文字、链接和图片附件；AI 操作画布；自动保存；撤销与重做；spec 编辑、恢复与 Markdown 导出。

暂不包含：多人协作、分享、云同步、注册登录 UI、文件夹、跨项目关联、手绘、自由形状、复杂排版、网页抓取、AI 图片识别、自动编写或执行项目代码、桌面安装包。

数据保存在本机，离线时可以查看和编辑；AI 需要本机 Codex 和网络连接。本地优先不代表本地模型推理。

## 3. 技术架构

- TypeScript 全栈，React + TanStack Start；TanStack Router 负责路由，TanStack Query 负责服务端状态与失效刷新。
- Node.js 本地服务负责 SQLite、附件文件、Codex App Server 子进程及 AI 操作校验；浏览器不直接访问文件系统或启动进程。
- SQLite 是项目内容的权威存储；图片文件保存在应用专用本地附件目录。
- 使用 React Flow（`@xyflow/react`）实现画布：自定义卡片、连线、平移缩放、多选、图片和程序化位置更新。布局策略由应用实现，操作与持久化通过领域层统一处理。
- 浏览器通过服务端函数/API 提交操作，通过流式连接接收 AI 文本、操作结果和运行状态。
- 服务默认只监听 loopback。写请求检查来源；附件仅能按数据库中的 ID 读取，不接受任意文件路径。
- 预留认证适配器与 owner 字段，当前始终解析为固定本地用户；不实现无实际用途的登录页面或虚假的认证流程。

## 4. 页面与交互

### 项目入口

支持创建、重命名、打开、删除项目，列表按最近更新时间排序。删除项目需确认，删除该项目关联数据；附件仅在没有引用后清理。空项目展示输入引导：“你想探索什么项目？”

### 项目工作区

- 主区域：无限画布，支持平移、缩放、适应全部内容和选中对象定位。
- 底部：固定 composer，可输入想法、回答问题、提出指令；显示当前选中的讨论范围，允许清除选择。
- 右侧：可收起的对话详情边栏，展示按时间排列的用户消息、AI 回复和操作摘要；关闭边栏不丢失对话。
- 顶部：项目名称、保存状态、Codex 状态，以及“生成 spec”按钮。
- spec 在可编辑文档面板中打开，支持返回画布、保存、导出 Markdown 和恢复记录。
- 面向桌面浏览器设计；MVP 不承诺手机编辑体验。

### 卡片与连线

卡片类型：

| 类型 | 用途 | 专属字段 |
| --- | --- | --- |
| 想法 | 目标、假设、候选方案、参考内容 | 无 |
| 问题 | 待澄清项、冲突和取舍 | 未解决 / 已解决，是否阻塞生成 |
| 决策 | 已确认的选择 | 决策理由 |
| 待办 | 后续可执行动作 | 待完成 / 已完成 |

所有卡片支持标题、正文、位置、尺寸、链接和图片附件。正文采用简单文本编辑；不提供复杂富文本排版。支持手动创建、编辑、拖动、多选、删除、连线和修改类型。链接保存原始网址并可打开，不自动抓取内容。

连线表达卡片关系，可带简短标签；删除卡片时一并删除其连线。图片可通过选择文件或粘贴加入，存储到本地附件目录；导入限制和失败原因须在 UI 清晰反馈。图片不会送入 AI，图片上的文字也不进入上下文。

新建卡片避免覆盖已有卡片；AI 默认只布局自己新增的内容。用户明确要求整理布局时，才移动已有内容。AI 操作完成后可定位相关卡片。

## 5. AI 行为

### Grill 工作方式

AI 是需求澄清伙伴：优先发现模糊目标、隐含假设、矛盾、过大范围和缺失的验收标准，并要求用户做具体取舍。每轮聚焦少量关键问题，避免一次倾倒大量问题。

AI 将稳定结论提炼为画布内容，不机械地把每条问答复制成卡片。未确定的内容保持为想法或问题；不得把 AI 的建议记为用户已确认的决策。决策记录理由；用户明确改变选择后更新相关决策，旧内容可从操作历史恢复。

当发现冲突，保留现有结论、创建或更新问题并追问。用户回答后解决问题、更新受影响卡片。AI 可以直接操作画布，无需逐次确认，包括创建、编辑、删除、连线和布局；这些操作必须可恢复。

### 上下文范围

未选择卡片时，以整个项目为讨论范围。选择卡片时，默认操作范围是选中卡片及其关系；提供必要的项目目标、决策和当前 spec 作为背景，并明确区分背景与可操作范围。涉及范围外内容时由用户扩大范围或明确授权。

发送时冻结本轮上下文，包含文本卡片、关系、相关对话和当前 spec。超出模型上下文时，优先保留用户本轮输入、选中卡片、已确认决策和未决问题；历史对话摘要需保留来源，不静默丢弃关键决策。

### 运行与操作接口

状态：空闲、连接中、生成中、正在应用操作、完成、失败、已停止。运行期间可继续手动编辑，但一个项目同时只允许一个 AI 任务。composer 提交和生成 spec 共用该限制。

AI 通过应用定义的结构化操作修改状态：读取画布上下文、创建/更新/删除卡片、创建/更新/删除连线、调整布局。生成 spec 通过独立操作写入文档。服务端校验项目归属、对象存在性、字段、引用和修订号，不执行模型输出中的任意代码或 SQL。

每批画布操作在单个 SQLite 事务中提交，并形成一个可撤销单元。任何操作不合法时整批不生效，错误反馈给 AI 修正。用户在运行中修改了目标内容时，拒绝过期更新并重新读取，避免覆盖用户编辑。

停止或连接中断后，不应用尚未提交的批次；已经提交的操作保留，可由用户撤销。失败不回滚无关的手动编辑，不丢失已保存消息；重试不会重复应用同一批操作。

## 6. 本机 Codex 接入

通过 Node-only 适配器启动已安装的 `codex app-server`，使用当前本机 Codex 登录。应用不收集或复制 API Key、Cookie、OAuth 文件或 ChatGPT 凭据。

实现前以本机 App Server 生成的协议 schema 验证兼容性。使用 stdio JSON-RPC，先 initialize，再 initialized，再创建线程和启动 turn；消费流式事件及完成/失败事件。应用持有对话与画布上下文，Codex 临时会话不作为数据存储。

每次连接使用空的临时工作目录、只读沙箱、never approval policy；启动子进程时不经过 shell。普通应用对话禁止 shell、任意文件访问、浏览器和外部工具。AI 的画布权限通过应用操作接口提供。

如果协议支持合适的动态工具调用，按实际 schema 接入；否则使用结构化输出 + 服务端校验执行 + 结果回传的应用工具循环。工具输入不能因来自模型而跳过校验。

取消任务和服务退出时终止关联子进程并清理本次临时目录。支持配置经过校验的 Codex 可执行文件绝对路径。未安装、未登录、网络失败、协议不兼容时，显示具体状态和可执行的修复提示；AI 不可用不影响本地编辑。

## 7. Spec 生成与维护

首次按钮文字为“生成 spec”，已有文档后为“更新 spec”。点击后读取当前画布、对话中的确认信息及用户手工编辑过的当前 spec。

如果缺少目标用户/问题或核心用户流程等基础信息，暂停生成，列出阻塞项并开始追问；不覆盖现有 spec。其他未决项不阻止生成草稿，但必须出现在文档中。AI 不得自行补成已确认需求。

文档至少包含：产品目标、用户与场景、范围与非目标、核心流程、功能要求、数据与持久化、AI 行为、异常处理、验收标准、未决问题。技术建议和未确认假设需明确标识。

只维护一份当前 spec，不提供多版本分支。每次 AI 覆盖或恢复前保存恢复快照；用户可查看并恢复旧内容。支持手工编辑、自动保存和 Markdown 导出。生成期间如果文档被手动修改，禁止直接覆盖，提示重新生成。

画布变化后标记“spec 可能需要更新”，不自动改写文档。生成失败保留当前文档，成功后以事务写入完整文档，避免半成品覆盖。

## 8. 数据模型与持久化

| 实体 | 主要字段 |
| --- | --- |
| Project | id、ownerId、name、createdAt、updatedAt、revision |
| CanvasNode | id、projectId、type、title、body、x/y、width/height、status、blocking、decisionReason、revision |
| CanvasEdge | id、projectId、sourceId、targetId、label、revision |
| Attachment | id、projectId、relativePath、originalName、mimeType、size、createdAt |
| NodeAttachment | nodeId、attachmentId |
| Message | id、projectId、role、content、runId、selectionContext、createdAt、status |
| AiRun | id、projectId、kind、status、error、startedAt、completedAt |
| OperationBatch | id、projectId、runId、forwardOperations、inverseOperations、createdAt、undoState |
| SpecDocument | projectId、content、revision、sourceProjectRevision、updatedAt |
| SpecSnapshot | id、projectId、content、createdAt、reason |

使用外键、事务和 schema migration。数据目录可配置，默认使用应用专用目录；不依赖源码仓库作为存储位置。附件保存相对路径，限制为支持的图片类型；写入失败不创建悬空引用。

用户编辑自动保存并显示“保存中 / 已保存 / 保存失败”；保存失败保留内存中的内容并允许重试。画布视口按项目保存在本机。重启时将未完成 AI 任务标记为中断，不静默重启。

撤销/重做以内容操作为单位，覆盖手动编辑和 AI 批次；拖动过程合并为一次操作。新操作发生后清空重做栈；撤销不删除聊天记录。spec 使用独立的恢复记录。MVP 不承诺应用重启后仍能继续撤销，恢复快照与已保存数据必须持久化。

## 9. 验收标准

1. 创建两个项目后，画布、对话和 spec 相互隔离；刷新与服务重启后数据仍存在。
2. 四类卡片可创建、编辑、拖动、删除、连线；文字、网址和图片可保存并重新打开。
3. 用户从底部 composer 提交想法，右侧出现流式回复；AI 能创建问题、记录用户确认的决策及理由。
4. 用户选择卡片提问时，AI 按该范围操作；未选择时可处理整个项目。
5. AI 能修改和删除画布对象；一次批次可完整撤销和重做，失败批次不留下部分结果。
6. AI 运行期间的手动修改不会被过期结果覆盖；停止运行后不会继续提交新批次。
7. 缺少基础需求时，生成按钮引导补全；一般未决问题会保留在生成草稿中。
8. 生成后可手动编辑 spec；再次生成更新同一份文档，可恢复覆盖前内容并导出 `.md`。
9. 本机 Codex 不可用时显示可理解的原因，仍可编辑已有项目；取消后无关联孤儿进程。
10. AI 输入不包含图片二进制、Codex 凭据或任意本地文件；模型构造的无效操作被服务端拒绝。
11. 浏览器刷新能恢复已持久化的对话与运行结果；失败重试不重复创建卡片。
12. 标准桌面环境下，以 200 张文本卡片和 300 条连线作为首轮画布验证数据集，确认平移、缩放、选择和拖动可用；量化性能阈值在实现基线测量后确定。

## 10. 实施顺序与验证

1. 建立 TanStack 应用、本地服务、SQLite migrations 和项目隔离；验证重启持久化。
2. 完成画布、卡片、连线、附件、自动保存与撤销；验证数据一致性与异常恢复。
3. 接通 Codex bridge、流式对话、取消与结构化画布操作；先做一轮真实协议 smoke test，再验证冲突和失败批次。
4. 实现 grill 行为、生成按钮、单份 spec、恢复记录与导出；用“开发这个工具”的真实流程端到端验收。

重点自动化检查：操作事务与逆操作、修订冲突、项目隔离、附件路径校验、spec 覆盖保护、取消清理。端到端检查核心闭环。构建检查确保 Node-only bridge 不进入浏览器 bundle。

## 11. 实现时需验证的事项

这些是工程验证项，不阻塞当前产品范围：React Flow 的交互与性能适配、本机 Codex 协议与动态工具能力、TanStack Start 的 Node 部署及流式响应接法、附件大小上限、实测性能基线。若验证结果要求改变上述用户行为，需重新对齐，不能静默缩减范围。
