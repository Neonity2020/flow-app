# 技术与产品决策

日期：2026-10-16。以下决定来自需求对齐；工程补充按本文标记。

| 决策 | 理由 / 影响 |
| --- | --- |
| 个人无限画布 | 优先支持自己的项目探索，暂不承担协作与权限复杂度 |
| AI 以 grill 为核心 | 通过追问、挑战假设和取舍推动项目，而非仅生成便签 |
| 底部 composer + 右侧对话 | 输入入口稳定，对话详情与主画布并存 |
| AI 可完全操作画布 | 操作经过领域接口，批次可撤销，并校验修订 |
| 想法 / 问题 / 决策 / 待办 | 区分假设、未决项、确认选择与后续行动 |
| 按钮生成单份 spec | 由用户触发更新；自动快照提供恢复，不做文档分支 |
| 本地 Web 应用 | 浏览器 UI + 本地 Node 服务；暂不打包桌面应用 |
| TanStack + TypeScript | Start 承载全栈应用，Router 管理路由，Query 管理服务端状态 |
| React Flow | 用户明确指定；使用 `@xyflow/react`，领域数据独立于组件内部状态 |
| SQLite + 本地附件目录 | 单机持久化与数据可控，预留 owner 和认证适配边界 |
| 本机 Codex | 复用本机登录；推理仍需联网，应用不复制凭据 |
| 图片展示、链接存储 | 第一版不抓网页、不识别图片，控制输入能力范围 |

## 工程补充

这些默认规则用于补齐实现细节，可在不改变产品目标时调整，并同步文档：SSE 作为拟定流式通道；连线允许环、拒绝自连与重复关系；画布操作使用批次 ID 幂等；数据版本使用乐观并发控制；SVG 不作为首批附件格式。

## 待验证项

- TanStack Start 的 Node 运行入口、流式连接和断线恢复实现。
- 已安装 Codex App Server 的协议、动态工具能力与取消行为。
- React Flow 自定义卡片和目标数据量下的交互性能。
- SQLite 驱动、migration 工具、图片大小上限和工具循环上限。

已完成的技术验证及实现细节见 [构建与验证记录](build-status.md)。若验证要求改变用户可见行为，应先更新 spec 并对齐；仅更换内部实现方案可以直接记录决定与依据。
