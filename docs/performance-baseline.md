# 画布首轮验收基线

日期：2026-10-16，Asia/Shanghai。对应 `spec.md` 验收 12 与 M2。

## 可重复运行

```sh
npm run bench:canvas
```

命令先构建生产产物，生成固定 ID 的 200 张文本卡片、300 条关系，测量存储操作，再启动 `127.0.0.1:3101/projects/canvas-benchmark`。`PORT` 可覆盖端口。数据始终放在新建的系统临时目录，忽略调用者已有的 `FLOW_DATA_DIR`，不会打开默认用户库。正常退出、SIGINT、SIGTERM 或服务器启动失败后删除临时目录；强制 SIGKILL 可能留下临时目录，需按控制台打印的路径清理。

卡片覆盖四类、1–4 行正文、问题阻塞标记与决策理由，按 20 列网格分布；关系包含相邻关系和跨行关系。无图片、外部链接或 AI 请求。固定数据构造位于 `scripts/canvas-fixture.ts`，通过真实 `applyOperations` 入库。

## 本机测量

Apple M2，macOS 内核 Darwin 25.6.0 arm64，Node v24.15.0；生产构建，SQLite WAL。基准项目的工作区 JSON 为 89,710 字节。以下为单次运行的 30 个顺序样本，包含 SQLite 和序列化开销；读取已经过种子写入预热，没有人为清空系统缓存。

| 操作 | 中位数 | P95 | 最大值 |
| --- | ---: | ---: | ---: |
| 读取完整工作区 | 0.76 ms | 0.88 ms | 1.07 ms |
| 移动一张卡片并撤销（两个事务合计） | 4.79 ms | 7.03 ms | 12.57 ms |

500 个创建操作原子写入耗时 7.46 ms（单样本）。存储测量使用另一个临时项目，测完删除，浏览器项目仍保留原始布局。

这些数字不包含网络、React 渲染或指针响应延迟，不能解读为 FPS 或端到端交互耗时。不同机器和负载不应直接套用这些数值作为阈值。

## 桌面浏览器功能验收

Codex 内嵌浏览器，1440×900 视口，生产服务与临时数据目录：

1. 加载后 DOM 中有 200 个卡片节点和 300 条关系，画布显示 200 张卡片。
2. 收起对话、适应全部内容、连续点击三次放大、滚动平移均可操作，视口 transform 随操作变化。
3. 框选 card-105、card-106，composer 显示选中 2 张卡片；选择操作不改变项目 revision。
4. 一次拖动同时移动两张卡片，持久化 revision 从 1 增到 2，两卡位移一致。
5. 点击一次撤销，两卡同时恢复原始坐标，其他 198 张卡片和 300 条关系保留。
6. 刷新后仍加载 200 张卡片、300 条关系，恢复平移缩放后的视口；控制台未记录 error 或 warn。

自动化存储测试覆盖同一数据集上的整批移动、撤销、重做，以及删除两卡后撤销恢复全部关联关系。浏览器操作目前为人工工具驱动验收，未纳入自动化 E2E。

## 结论与后续

验收 12 的首轮功能检查通过，已建立存储耗时基线。尚未测量浏览器 FPS、长任务、峰值内存、指针响应延迟，也未制定量化渲染性能门槛；不能据此宣称所有设备上流畅。后续如观察到卡顿，先补浏览器性能 trace，再决定视口裁剪、memo 或其他优化，不凭存储数字修改渲染策略。
