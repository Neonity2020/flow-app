# 产品与交互

## 核心体验

用户创建项目，在底部 composer 输入模糊想法。AI 在右侧对话栏追问，并将想法、问题、决策和待办整理到主画布。用户通过回答和手动编辑推进讨论，点击顶部按钮生成或更新唯一一份 spec。

第一版服务于个人项目探索。AI 应要求用户取舍，不把建议伪装成已确认结论。

## 页面结构

拟定路由：`/` 为项目列表，`/projects/$projectId` 为工作区。spec 作为工作区文档面板打开，保留项目上下文和画布视口。

项目列表支持创建、重命名、按更新时间排列和确认删除。空列表提供创建入口；不存在的项目显示返回列表入口。

工作区包含顶部工具区、React Flow 画布、底部 composer、右侧对话详情和可切换的 spec 面板。顶部展示保存状态及 Codex 状态。“生成 spec”在已有文档后变为“更新 spec”。

## 画布操作

- 支持平移、缩放、框选、多选、定位选中项、适应全部内容。
- 卡片可创建、编辑、拖动、删除、切换类型；支持带标签的连线。
- 类型为想法、问题、决策、待办。问题显示解决状态及阻塞标记；决策显示理由；待办显示完成状态。
- 支持文字、网址和图片。图片通过文件选择或粘贴导入；网址不抓取，图片不识别。
- 卡片编辑时，删除键和撤销快捷键优先交给文本编辑器；未编辑文本时才触发画布操作。
- 拖动期间本地即时反馈，结束时形成一次持久化操作。新卡片放到可用区域，AI 不随意移动用户已有布局。

## 对话与范围

发送时记录选中卡片 ID 和上下文版本。composer 展示“整个项目”或选中范围，并允许清除。提交后改变选择不改变进行中任务的范围。

右栏展示完整对话、运行状态、操作摘要和关联对象定位入口。画布保留提炼后的知识，不逐条复制问答。关闭右栏不取消任务。

同项目只允许一个 AI 任务；运行中可编辑画布和停止 AI，不能重复提交或同时生成 spec。停止后保留已提交操作，明确显示本轮已停止。

## Spec 流程

点击按钮后，AI 检查目标用户/问题和核心流程是否足够明确。基础信息不足时进入追问，保留当前 spec；普通未决问题写进草稿。生成成功后打开文档。

文档可编辑、自动保存、导出 Markdown、查看恢复记录。再次生成纳入手工编辑内容；覆盖前留快照。若生成期间文档被编辑，则拒绝过期覆盖，并提供重新生成入口。

画布变化只提示“spec 可能需要更新”，不自动重写。恢复旧文档前也保存当前文档快照。

## 状态反馈

保存状态为保存中、已保存、保存失败；失败内容留在内存并允许重试。AI 状态为连接中、生成中、应用操作、完成、失败、已停止。错误提示应区分未安装 Codex、未登录、网络失败、协议不兼容和操作冲突。

离线仍可编辑本地数据。刷新丢失未成功保存内容的风险须通过明确的失败状态及离开提醒降低。第一版面向桌面，不承诺手机编辑体验。
