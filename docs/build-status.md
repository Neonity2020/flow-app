## 工程落地说明

第一版使用项目级画布 JSON 快照存储节点和连线，以单事务批次操作实现一致性；历史记录保存前后快照。`data-model.md` 中的节点、连线和关联表为逻辑模型，尚未拆为独立 SQL 表。并发检查使用更保守的项目级 revision：任意画布内容变化都会拒绝过期 AI 批次，不会自动覆盖新编辑。spec 使用独立 revision。

固定宽度卡片由内容决定高度；暂不提供手工调整尺寸。视口保存在 localStorage，选择仅为 UI 状态。图片采用 10 MB 上限。流式通道使用 SSE，事件写入 SQLite 并支持按序号重放。

Codex 当前版本通过 `initialize → initialized → thread/start → turn/start` 和结构化输出接入。没有假设动态工具可用；应用负责执行结构化操作。

## 当前限制与后续工作

- 长上下文超过 160,000 字符会明确停止并保留数据；自动摘要压缩尚未实现。
- 用户编辑造成 AI 修订冲突时保留现状并报告失败，需要重新提交；不会自动重写用户内容。
- 首版没有完整项目备份 UI；Markdown 导出只导出当前 spec。
- 后续数据库升级需要在 migration 中补充升级前一致性备份；目前仅存在空库初始化 migration。
- 断电、磁盘满、跨标签页持续并发，以及跨 Codex 版本兼容性仍需更深入的故障演练。

不应将本记录中的后续工作静默视为完成；继续实施时沿用 `implementation.md` 的验收编号。
